# 겨울파트너 AI 기능 개선 계획

## Context

기획서의 35개 기능이 모두 구현·배포됐고(운영: winter-partner.vercel.app), 개인정보 단계(P13)가 진행 중이다. 다음 개선 축으로 AI를 검토한다. 우선 영역은 **샵 운영 효율**, 모델은 **Claude API**, 범위는 **후보 전부를 계획에 넣고 단계로 나눈다**.

현재 코드에서 AI가 들어갈 자리는 이미 구조화돼 있다: 강습 등록 검증(`src/lib/shop/job.ts` `parseJob`), 강사 찾기 정렬(`supabase/migrations/20261101151500_search_instructors.sql`: 전속 우선 → 평점 → 강습 횟수), 입찰 선정 화면(`src/app/shop/jobs/[id]/select-bid-form.tsx`), 손님 카드(`src/app/shop/customers/`), 수업 메모(`src/app/instructor/report-form.tsx`, `previous-notes.tsx`), 자격증 검증(`src/app/admin/`, `src/lib/instructor/cert.ts`), 건강정보 안내(`src/lib/privacy/texts.ts`, P13-4). 외부 API 호출 패턴은 `src/lib/notify/dispatch.ts`(web-push, 서버 전용)와 같다.

목표: 사장님이 카톡으로 받은 예약을 30초 안에 강습으로 등록하고, 강사를 고를 때 근거를 보고, 자격증 검증과 손님 관리에 드는 손을 줄인다. AI는 **제안만** 하고 확정은 사람이 한다.

## 공통 원칙

- **AI는 제안, 확정은 사람**: 모든 AI 출력은 폼 미리 채우기·추천 표시·초안으로만 쓴다. DB에 바로 쓰지 않는다.
- **개인정보 최소 전송**: 이름·연락처·보호자 정보는 AI에 보내지 않는다. 손님은 "손님A"로 치환하고 레벨·메모·강습 조건만 보낸다. 자격증 이미지는 강사 본인 동의(업로드 화면 안내)로 전송.
- **재위탁 고지**: 외부 AI 처리는 개인정보 보호법상 재위탁에 해당할 수 있다. 샵 가입 약관(P13-7)의 위탁 조항과 플랫폼 처리방침의 수탁자 목록에 Anthropic을 추가한다. Anthropic API는 기본적으로 입력을 학습에 쓰지 않으며 보관 정책을 처리방침에 적는다. **법률 검토 항목**.
- **끄면 그대로 동작**: `ANTHROPIC_API_KEY`가 없거나 샵 설정에서 끄면 모든 기능이 기존 수동 흐름으로 돌아간다. E2E는 AI 끈 상태로 돈다.
- **비용 상한**: 샵별 하루 호출 수 상한(기본 200회), 플랫폼 전체 월 비용 상한. 넘으면 조용히 비활성화하고 관리자에게 알림.
- **모델**: 텍스트 구조화·요약은 `claude-haiku-5-5`(싸고 빠름), 이미지 판독·입찰 분석은 `claude-sonnet-5-5`. 모델명은 설정값으로.

## Phase 0. 공통 기반 (모든 기능의 전제)

새 파일:
- `src/lib/ai/client.ts` (`server-only`): Anthropic SDK 래퍼. `callStructured<T>(feature, prompt, schema, opts)` 한 함수. JSON 스키마 강제(tool use), 15초 타임아웃, 재시도 1회, 실패 시 `null` 반환(호출부가 수동 흐름으로).
- `src/lib/ai/redact.ts`: 손님 이름·전화·이메일 치환, 건강 단어 마스킹. 단위 테스트 필수.
- `src/lib/ai/flags.ts`: `isAiEnabled(shopId, feature)` — `app_settings`(`20261102000150_app_settings_rls.sql` 참고)에 플랫폼 기본값, `shops.ai_features jsonb`에 샵별 on/off.
- 마이그레이션 `ai_usage(id, shop_id, user_id, feature, model, input_tokens, output_tokens, cost_krw, ok, created_at)` + RLS(샵은 자기 것, 관리자 전체) + 일일 상한 확인 함수 `private.ai_quota_ok(shop_id)`.
- 관리자 화면 `/admin/ai`: 기능별 사용량·비용·실패율, 플랫폼 기본값 토글.
- 환경변수 `ANTHROPIC_API_KEY`, `AI_MONTHLY_CAP_KRW` (Vercel production에만, `.env.local.example`에 설명 추가).
- `scripts/security-check.mjs`에 패턴 추가: `sk-ant-` 키 유출 검사.

## Phase 1. 이번 시즌, 시범 운영 전 (샵 운영 효율)

### A1. 강습 접수 자동 입력 (효과 가장 큼)
- 위치: `/shop/jobs/new` 상단에 "문자·카톡 붙여넣기" 칸. 서버 액션이 `callStructured`로 날짜·시작/끝 시간·종목·강습 유형·인원·레벨·요청 사항·패치 언급을 추출 → 기존 폼(`job-form.tsx`)의 필드를 미리 채움. 저장 검증은 그대로 `parseJob`.
- 손님 연결: 추출한 손님 이름으로 `customers`를 샵 범위에서 검색해 후보 표시(이름은 AI에 보내되 연락처는 보내지 않는다 → 재위탁 고지 대상. 이름까지 빼고 싶으면 "손님 이름은 직접 선택" 옵션).
- 상대 날짜("이번 주 토요일")는 서버에서 KST 기준 오늘 날짜를 프롬프트에 넣어 해석. 확신 없는 필드는 비워 두고 노란 테두리로 표시.
- 평가 세트: 실제 접수 문자 형태 20개(사장님이 샘플 제공) → `src/lib/ai/__fixtures__/`에 두고 추출 정확도 테스트.

### D1. 자격증 자동 판독
- 위치: 강사 업로드 직후(`src/app/instructor/profile/cert-actions.ts`)와 관리자 검증 목록(`/admin`).
- `claude-sonnet-5-5` 비전으로 발급처·등급·성명·발급일·유효기간·자격번호 일부를 추출해 `instructor_certs.ai_extract jsonb`에 저장. 관리자 화면에 "강사 입력값 vs 판독값" 나란히 표시, 불일치는 빨강. **승인은 사람**.
- 성명 불일치(프로필 이름 ≠ 자격증 성명)는 자동으로 "확인 필요" 표시.
- 업로드 화면에 "검증을 위해 자격증 이미지가 AI 판독 서비스로 전송됩니다" 안내.

### A3. 입찰 선정 보조
- 위치: 강습 상세 입찰 현황(`select-bid-form.tsx`) 위에 요약 카드.
- 입력: 입찰 목록(금액·한마디), 각 강사의 평점·강습 횟수·검증 자격증·패널티 점수·이 샵과의 과거 강습 수(모두 이미 DB에 있음), 공고 조건(레벨·인원·유아 여부). 이름 대신 "강사1·2·3"으로 보내고 화면에서 되돌림.
- 출력: 추천 1명 + 이유 2줄, 각 입찰의 장단점 한 줄, 이상 표시(상한의 50% 미만 금액, 패널티 3점 이상, 한마디와 조건 불일치).
- 버튼 "추천대로 선택"은 기존 선정 폼을 채우기만 한다.

## Phase 2. 시즌 중 (강사·손님 관리)

### A4. 손님 카드 요약과 다음 연락 제안
- 손님 카드(`/shop/customers`)에 "요약" 상자: 강습 이력·강사 수업 메모·연락 기록(`customer_contacts`)을 넣어 3줄 요약 + "다음 강습 제안" + 연락 문구 초안. 개인정보는 치환.
- 캐시: `customers.ai_summary`, `ai_summary_at`. 메모·강습이 바뀐 뒤 처음 열 때만 재생성.

### B1. 수업 메모 정리 (강사)
- 완료 보고(`report-form.tsx`)에 "정리하기" 버튼: 짧은 메모나 음성 받아쓰기(브라우저 Web Speech API, 로컬 처리) → 진도·잘된 점·다음 과제 3항목으로 정리. 저장은 강사가 수정 후.
- P13-4 건강정보 경고와 결합: 정규식 1차 → AI가 "건강 정보로 보이는 문장" 2차 표시, 강사가 지우도록 유도. 저장을 막지는 않는다.

### D2. 건강정보 감지 강화
- `src/lib/ai/redact.ts`의 정규식에 AI 분류를 덧붙여 손님 메모·수업 메모 저장 시 경고 정확도 향상. 호출은 메모 길이 20자 이상일 때만.

## Phase 3. 비시즌 (매출·신뢰)

### C1. 재방문 후보와 안내 문구
- 마케팅 수신 동의(P13-1 동의 기록)가 유효한 손님만 대상. 지난 시즌 강습 횟수·레벨·마지막 강습일로 후보 목록(SQL) → AI가 손님별 안내 문구 초안(레벨 다음 단계 제안). 발송은 알림톡 광고 템플릿 제약 때문에 샵이 직접 보내는 "복사용 문구"로.

### B2. 입찰 금액 참고 (강사)
- AI 불필요. 같은 스키장·종목·유형의 최근 30일 낙찰가 중앙값·범위를 SQL 뷰로 입찰 화면에 표시. 설명 문구만 AI(선택).

### D3. 이상 패턴 탐지
- 규칙 기반 먼저(같은 강사 일방 취소 2회/주, 같은 샵 입찰 반복 미선정 후 직거래 의심 신호 없음 등). AI는 관리자 화면에서 "이 강사의 최근 활동 요약"으로만.

### E. 관리자 데이터 질의
- `/admin`에서 "이번 달 샵별 강습 수는?" 같은 질문 → SQL 생성은 하지 않고, 미리 정의한 집계 함수 10개 중 하나를 AI가 고르는 방식(안전). 후순위.

## 검증

- 단위: `client.ts`는 SDK를 목으로 대체해 스키마 강제·타임아웃·`null` 반환을 테스트. `redact.ts`는 이름·전화·건강 단어 치환 케이스 30개.
- A1 정확도: 평가 세트 20개 중 날짜·시간·종목·인원 4개 필드 모두 맞는 비율 90% 이상을 통과 기준으로(실제 API 호출 테스트는 `AI_EVAL=1`일 때만, CI 제외).
- E2E: 기존 8개는 AI 끈 상태로 그대로 통과해야 한다. AI 켠 E2E 1개(붙여넣기 → 폼 채움 → 저장)는 목 응답으로.
- 운영: `npm run check:prod`에 "/shop/jobs/new가 키 없이도 200" 항목 추가. 배포 후 `/admin/ai`에서 호출·비용이 기록되는지 확인.
- 보안: pre-push 점검에 `sk-ant-` 패턴, RLS pgTAP에 `ai_usage` 샵 격리 추가.
