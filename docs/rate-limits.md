# 요청 횟수 제한 (P16-3)

값은 `src/lib/ops/limits.ts` 한 곳에 있다(DB 트리거 한도는 `private.app_settings`의 `limit_*`, 없으면 마이그레이션 기본값). 바꾸면 이 문서도 함께 고친다.
카운터는 DB `private.rate_limits`(고정 창)에 있다. 키는 IP·이메일 원문이 아니라 해시 앞 32자다. 하루 지난 기록은 자동으로 지운다.
DB 오류가 나면 막지 않는다. 정상 사용을 우선한다.

| 이름 | 무엇을 | 기준 | 한도 | 세는 것 | 근거 |
|---|---|---|---|---|---|
| `login_account` | 로그인 | 계정(이메일) | 10분에 10번 | **실패만** | 비밀번호를 10번 연속 틀리는 정상 사용자는 드물다. 비밀번호 대입은 계정당 시간당 60번 이하로 묶인다. 맞게 로그인하는 것은 세지 않는다 |
| `login_ip` | 로그인 | IP | 10분에 30번 | **실패만** | 매장 와이파이 하나로 직원 여러 명이 접속한다. 계정 한도의 3배로 잡아, 같은 매장의 몇 명이 틀려도 막히지 않는다 |
| `signup_ip` | 가입 | IP | 1시간에 10번 | 모든 시도 | 샵 한 곳이 사장님과 직원 몇 명을 한 번에 가입시켜도 충분하다. 가짜 계정을 대량으로 만드는 것은 막는다 |
| `reset_account` | 비밀번호 재설정 메일 | 계정 | 1시간에 3번 | 모든 시도 | 메일이 늦게 와서 다시 누르는 경우까지 넉넉하다. 남의 메일함에 메일을 퍼붓는 것은 막는다 |
| `reset_ip` | 비밀번호 재설정 메일 | IP | 1시간에 10번 | 모든 시도 | 여러 계정으로 돌아가며 메일을 보내는 것을 막는다. 메일 발송 한도(Supabase 시간당)도 아낀다 |
| `link_view_ip` | 동의 링크·셀프 등록 링크 열기 | IP | 10분에 60번 | 모든 열람 | 손님은 보통 한두 번 연다. 링크 토큰을 대입해 맞히려는 시도를 막는다 |
| (기존) 동의 제출 | 동의 링크 제출 | IP | 10분에 20번 | 모든 시도 | P13 |
| (기존) 셀프 등록 제출 | QR 등록 | IP / 링크 | 10분에 10번 / 하루 300번 | 모든 시도 | P13 |
| `ai_user` | AI 호출 | 사용자(없으면 샵) | 10분에 30번 | 모든 호출 | 접수 문자를 연달아 붙여도 1분에 3번 정도면 충분하다. 샵 하루 200회 상한과 월 비용 상한은 그대로 둔다. 넘으면 조용히 수동 흐름으로 돌아간다 |
| `feedback_ip` | 의견 보내기 (P16-6) | IP | 1시간에 10번 | 모든 시도 | 한 사람이 한 시간에 의견을 10번 넘게 보낼 일은 드물다. 로그인 없이도 열려 있는 폼이라 도배를 막는다 |
| `consult_conversation` | AI 상담 카카오 웹훅 (P22-3) | 대화(손님 한 명) | 10분에 20번 | 모든 메시지 | 손님이 질문을 나눠 보내도 10분에 20번이면 충분하다. 넘으면 AI를 부르지 않고 "상담 연결" 안내만 보낸다(메시지는 저장). AI 호출 자체는 `ai_user`(대화 단위 10분 30번)·샵 하루 300회 상한도 따른다 |
| `consult_shop` | AI 상담 카카오 웹훅 (P22-3) | 샵 | 10분에 300번 | 모든 메시지 | 성수기 주말에 손님 여러 명이 동시에 물어도 넉넉하다(대화 한도의 15배). 웹훅 주소가 새어 도배될 때 저장·AI 비용을 막는다. 넘으면 저장하지 않고 "상담 연결" 안내 |

| DB `limit_offers_per_hour` (보안 10) | 강습 의뢰 보내기 | 사용자 | 1시간에 100번 | 모든 의뢰 | 의뢰마다 강사에게 알림이 간다. 성수기 하루 의뢰량보다 넉넉하다 |
| DB `limit_cert_files` (보안 10) | 자격증 파일 | 강사 폴더 | 30개 | 폴더 안 파일 수 | 자격증은 몇 개뿐이다. Storage API로 파일만 계속 올리는 것을 막는다 |

## 넘었을 때
- 로그인·가입·재설정: 폼에 "요청이 너무 많습니다. 10분(1시간) 뒤에 다시 시도해 주세요."가 뜬다.
- 동의·셀프 등록 링크: "잠시 쉬었다가 다시 열어 주세요" 안내 화면이 뜬다 (`src/components/rate-limited.tsx`).
- AI: 버튼을 눌러도 제안이 나오지 않고, 손으로 입력하는 원래 흐름이 그대로 동작한다.
- AI 상담(카카오): 손님에게 "메시지가 많아 자동 답변을 잠시 쉬어요…" + 상담 연결 버튼이 간다. AI는 부르지 않는다.
- AI 상담(인스타, P22-4): 같은 `consult_shop`·`consult_conversation`을 쓴다. 샵 한도를 넘으면 저장하지 않고, 대화 한도를 넘으면 저장만 하고 답하지 않는다(인스타는 손님이 먼저 보낸 뒤 24시간 안에만 보낼 수 있어 안내를 반복하지 않는다). 웹훅은 서명(앱 시크릿 HMAC)이 틀리면 저장 전에 400으로 끊으므로 IP 한도는 두지 않는다.

## IP
Vercel이 붙이는 `x-forwarded-for`의 첫 값을 쓴다. Vercel 앞단이 이 값을 덮어쓰기 때문에 사용자가 꾸며 보낼 수 없다.

## Supabase Auth 자체 한도 (참고, 사장님 확인)
Supabase Auth에도 IP별 한도가 따로 있다. 원격 값은 기본값과 같다: 로그인·가입은 5분에 30번, 메일은 시간당 2통.
우리 앱은 로그인을 **서버(Vercel)에서** 호출한다. 그래서 Supabase가 사용자 IP 대신 Vercel 서버 IP 기준으로 셀 수 있다. 그러면 여러 사용자가 한 한도를 같이 쓰게 된다.
시범 운영 중에 "잠시 후 다시 시도해 주세요"가 자주 보이면 Supabase 대시보드 → Authentication → Rate Limits에서 `sign_in_sign_ups`를 올린다. 이것은 운영 설정 변경이라 사장님이 정한다.
