자동화(e2e/rehearsal.spec.ts, 로컬·AI 가짜 모델)로 확인한 것과, 사람이 실제 기기에서 확인해야 하는 것.

## 자동으로 확인함 (로컬, 8단계 모두 통과)
| # | 시나리오 | 결과 |
|---|---|---|
| 1 | 접수 문자 붙여넣기 → 칸 채움 → 직접 의뢰 → 전속 강사 수락 | 통과 |
| 2 | 입찰 공고(팀 허용) → 전속 강사에겐 안 보임 → 프리랜서 2·팀 1 입찰 → AI 추천 → 팀 선정 → 팀원 지정 | 통과 |
| 3 | 샵 간 같은 시간 의뢰(이미 확정된 강사는 다른 샵 후보에서 빠짐), 강사 일방 취소 → 패널티 1점, 손님 취소 | 통과 |
| 4 | 완료 보고·수업 메모 → 승인 → 월 정산(전속·프리 3.3%, 팀 0%) → 발행 → PDF·Excel → 지급 완료, 팀 승인 알림(팀원 금액 없음) | 통과 |
| 5 | 알림 목록 → 모두 읽음 → 읽지 않음 0 | 통과 |
| 6 | 14세 미만 손님 + 보호자 동의 링크, 삭제(익명화) 요청, 연락처 열람 접속 기록 | 통과 |
| 7 | 샵 간 격리: 다른 샵 강습 URL·직접 조회 6개 테이블·남의 손님 수정·남의 샵 강습 등록·정산 지급 표시 시도 | 모두 차단 |
| 8 | 폭 390px 화면 14개 가로 넘침 없음, 캡처 test-results/rehearsal-mobile/ | 통과 |

운영(Vercel)에서도: 정산 집계 → 정산서 PDF(한글 글꼴, 1.6MB, 2.1초)·Excel 정상 (e2e-prod/p15-4-settlement.spec.ts).

## 사람이 실제 기기에서 확인할 것
- [ ] 웹푸시: 안드로이드 크롬·아이폰 사파리(홈 화면 추가 후)에서 알림 켜기 → 의뢰 보내기 → 휴대폰에 알림이 실제로 뜨는지, 누르면 해당 화면으로 가는지
- [ ] PWA: 홈 화면 추가, 앱처럼 열림, 비행기 모드에서 오프라인 화면
- [ ] QR 셀프 등록: 인쇄한 QR을 휴대폰 카메라로 찍어 등록까지 (카메라 앱 → 브라우저 전환)
- [ ] 동의 링크를 문자·카톡으로 보냈을 때 미리보기·열림
- [ ] 음성 입력(말로 입력): 크롬 안드로이드에서 마이크 권한·인식 품질
- [ ] 정산서 PDF를 휴대폰에서 열었을 때 글자 깨짐 없음, 인쇄
- [ ] 실제 강사 자격증 사진(흐릿함·기울어짐·빛 반사)으로 판독 품질
- [ ] 실제 접수 문자 20개로 자동 입력 정확도 (지금은 가상 샘플 기준)
