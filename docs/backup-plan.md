# 백업 계획 (시범 샵 실데이터 전)

지금 운영 DB(Supabase `winter-partner`)는 무료 요금제라 **자동 백업이 없습니다**. 시범 샵의 실제 손님·정산 데이터가 들어오기 전에 아래 둘 중 하나를 정해야 합니다. 요금제 변경·결제는 사장님이 직접 하십니다.

## 선택지

| | A. Supabase Pro 전환 (추천) | B. 손 백업 유지 |
|---|---|---|
| 비용 | 월 약 25달러(조직당, 기본 사용량 포함) | 0원 (사람 시간) |
| 자동 백업 | 매일, 최근 7일 보관 | 없음 — 아래 절차로 사람이 뜸 |
| 시점 복구(PITR) | 추가 옵션(월 약 100달러부터, 7일 안 아무 시각으로) — 시범엔 불필요 | 없음 |
| 잃을 수 있는 데이터 | 최대 하루 | 마지막 손 백업 이후 전부 |
| 그 밖에 | 일시 정지 없음(무료는 1주 미사용 시 정지), 더 큰 DB·저장소, 이메일 지원 | — |

- 요금은 2026년 11월 기준 기억입니다. **전환 전에 supabase.com/pricing에서 다시 확인**해 주세요.
- **추천**: 시범 샵 실데이터가 들어오는 날 **전에** Pro로 올립니다. 하루치 이상 정산·손님 기록을 잃는 위험이 월 25달러보다 큽니다. 시점 복구 옵션은 샵이 늘어난 뒤에 다시 봅니다.
- Pro로 올려도 **월 1회 손 백업은 계속**합니다(Supabase 계정 문제·실수로 프로젝트 삭제 대비, 7일보다 오래된 시점 보관).

## 손 백업 절차 (`scripts/ops/db-backup.sh`)
읽기만 하는 스크립트입니다. 운영 데이터를 바꾸지 않습니다.

**준비 (한 번)**: Mac에 Docker 실행, 저장소 폴더에서 `npx supabase login`, `npx supabase link --project-ref <프로젝트 ref>`.

**실행**
```bash
bash scripts/ops/db-backup.sh
# → backups/20261210-2300/ 아래 schema.sql, data.sql, roles.sql
```

**주기**
- Pro 전환 전(무료 요금제): 시범 기간에는 **매일 밤 영업 끝난 뒤** 1회, 정산서 발행일(월초)에는 발행 직후 1회 더.
- Pro 전환 후: 월 1회(정산서 발행 직후) + 큰 마이그레이션 적용 직전.

**보관**
- `backups/`는 git에 올라가지 않습니다. 손님 연락처가 들어 있으니 **암호화된 곳에만** 옮깁니다: 암호를 건 압축 파일(`zip -e`)을 회사 구글 드라이브의 공유 안 된 폴더 또는 암호화한 외장 디스크.
- 보관 기간: 최근 14일치 + 월말 것 12개월. 오래된 것은 지웁니다(개인정보 보관 기간 규칙과 맞춤, `docs/plans/P13-privacy.md`).
- 노트북 안의 `backups/`는 옮긴 뒤 지웁니다.

## 복구 연습 (월 1회, 로컬에서만)
운영 DB에는 절대 복구하지 않습니다. 연습은 내 Mac의 로컬 Supabase로 합니다.
1. `npx supabase start` (로컬)
2. 로컬 DB를 비우고 백업을 넣기:
   ```bash
   npx supabase db reset --no-seed
   eval "$(npx supabase status -o env | grep '^DB_URL=')"   # 로컬 DB 주소
   psql "$DB_URL" -f backups/<날짜>/roles.sql
   psql "$DB_URL" -c "set session_replication_role = replica" -f backups/<날짜>/data.sql
   ```
3. 확인: 로컬 앱(`npm run dev`)에 시범 샵 계정으로 로그인 → 손님 수, 지난달 정산서 금액이 운영 화면과 같은지 3곳 비교.
4. 결과(날짜·걸린 시간·차이)를 이 문서 아래 표에 적습니다.
5. 끝나면 `npx supabase db reset`으로 로컬을 다시 시드 데이터로 돌립니다(실데이터를 로컬에 남기지 않음).

| 날짜 | 백업 시각 | 복구에 걸린 시간 | 비교 결과 | 한 사람 |
|---|---|---|---|---|
| | | | | |

## 실제 장애 때 (운영 복구)
- Pro: 대시보드 → Database → Backups → 원하는 날짜 **Restore**. 그 시각 이후 데이터는 사라지니, 먼저 지금 상태를 손 백업으로 떠 둡니다.
- 무료: 새 Supabase 프로젝트를 만들어 위 2단계처럼 넣고 앱 환경변수를 바꿔야 합니다(반나절). 그래서 Pro를 추천합니다.
- 어느 쪽이든 복구는 되돌릴 수 없는 작업이라 사장님 확인 후에만 합니다.
