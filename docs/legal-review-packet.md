# 법률 검토 의뢰서 — 겨울파트너 개인정보·약관

> 이 문서는 변호사님께 **검토를 부탁드리는 질문 모음**입니다. 문서 안의 설계·문구는 모두 저희가 만든 초안이며, 법률 자문이나 법적 판단이 아닙니다. 맞는지 여부를 여쭙는 것입니다.
>
> 작성: 2026-11-05 · 요청자: 겨울파트너 대표 · 회신 받을 곳: [연락처 — 사장님이 채움]

## 1. 의뢰 개요

**서비스 한 줄 설명**: 스키·스노보드 렌탈샵·강습팀(이하 "샵")과 강습 강사를 잇는 B2B 웹 서비스입니다. 샵이 강습을 올리면 강사에게 직접 의뢰하거나 입찰을 받고, 강습이 끝나면 월 단위 정산서를 만들어 줍니다. 송금은 샵이 직접 하고 저희는 대금을 받거나 보내지 않습니다(PG 없음).

**개인정보 관계(저희가 이해한 구조, 확인 부탁)**:
- 손님 정보(이름·연락처·출생연도·레벨·장비 치수·메모, 14세 미만은 보호자 이름·연락처)의 **처리자는 각 샵**, 겨울파트너는 샵의 위탁을 받는 **수탁자**.
- 회원 정보(샵 관리자·강사의 이름·이메일·휴대폰, 강사 자격증 파일)는 겨울파트너가 직접 처리.
- 겨울파트너가 다시 맡기는 업체(재위탁): Supabase(DB·인증·파일, 서울 리전), Vercel Inc.(웹 호스팅, 미국 회사), 웹푸시 서비스, Anthropic PBC(미국, AI 기능). 앞으로 ㈜카카오, Meta Platforms, Inc.(미국)가 AI 상담 경로에 들어갑니다.

**일정**:
| 시점 | 내용 |
|---|---|
| 2026-11 말 | 시범 샵(몇 곳) 실제 사용 시작 예정 — 그 전에 처리방침·약관을 게시해야 합니다 |
| 2026-12 중순 | 작업 목록상 검토 마감 목표 (P13-7: 12/17, P14-5: 12/23, P21-9: 12/20) |
| 2026-27 겨울 시즌 | 정식 운영 |

시범 전에 꼭 필요한 것과 시즌 중 고쳐도 되는 것을 나눠 주시면 큰 도움이 됩니다.

## 2. 검토 대상

### (a) 처리위탁 조항·이용약관·개인정보 처리방침 (작업 P13-7)

**초안 위치**
| 내용 | 파일 |
|---|---|
| 이용약관 (6항 손님 정보의 주인, 7항 개인정보 처리위탁) | `src/app/terms/page.tsx` (화면 주소 `/terms`) |
| 개인정보 처리방침 (1~9항) | `src/app/privacy/page.tsx` (화면 주소 `/privacy`) |
| 샵이 손님에게 게시하는 위탁 고지·손님 안내·선택 동의 문구 템플릿 | `src/app/shop/privacy-notice/page.tsx` (화면 주소 `/shop/privacy-notice`) |
| 손님 안내·선택 동의(광고 문자·사진) 문구와 버전 | `src/lib/privacy/texts.ts` |
| 샵 탈퇴 때 손님 정보 내보내기·파기 절차 | `docs/shop-offboarding.md` |

화면 문구에는 모두 "초안 — 법률 검토 전"이 표시돼 있습니다.

**이미 정한 설계 원칙**
- 모든 샵 자료는 샵별로 격리하고, DB 접근 규칙으로 다른 샵·본사·강사가 볼 수 없게 강제합니다.
- 손님 연락처는 **그 샵 관리자만** 봅니다. 본사 관리자도 볼 수 없습니다. 강사는 손님의 레벨·메모만 봅니다.
- 약관 7항은 개인정보 보호법 제26조 1항의 문서 요건을 따르려고 했습니다: 목적·범위, 목적 외 처리 금지, 기술적·관리적 보호조치, 재위탁 제한, 관리·감독, 보관·파기, 손해배상.
- 손님 정보는 마지막 강습 후 3시즌이 지나면 익명화합니다. 손님이 삭제를 요청하면 샵이 즉시 익명화합니다.
- 손님 연락처 열람·다운로드는 접속 기록으로 남기고(수정·삭제 불가) 2년 보관합니다.
- 주민등록번호·계좌번호는 받지 않습니다.
- 샵 탈퇴 시: 샵이 원하면 손님 목록을 암호 걸린 Excel로 돌려주고, 확인 후(또는 요청일로부터 30일 뒤) 익명화합니다. 거래 기록은 법정 기간 동안 따로 보관합니다.
- 문구를 바꾸면 버전을 올려 누가 어떤 문구에 동의했는지 남깁니다.

### (b) AI 재위탁(Anthropic PBC, 미국)·국외 이전 (작업 P14-5)

**초안 위치**
| 내용 | 파일 |
|---|---|
| 처리방침 4항 재위탁 업체 Anthropic 줄 | `src/app/privacy/page.tsx` |
| 약관 7항 AI 도우미 재위탁 | `src/app/terms/page.tsx` |
| 샵용 위탁 고지의 재위탁 줄(AI를 쓰는 샵만 게시) | `src/app/shop/privacy-notice/page.tsx` |
| AI로 보내기 전에 개인정보를 지우는 코드 | `src/lib/ai/redact.ts` |

**이미 정한 설계 원칙**
- AI 기능: 강습 접수 글 정리, 자격증 이미지 판독, 입찰 비교, 손님 카드 요약, 수업 메모 정리, 안내 문구 초안.
- AI는 **제안만** 하고 확정은 사람이 합니다. AI 결과를 DB에 바로 쓰지 않습니다.
- 보내는 정보 최소화: 연락처·이메일·보호자 정보는 지우고, 샵에 이미 등록된 손님 이름은 "손님A"처럼 바꿔 보냅니다. **접수 글 속 처음 보는 이름은 남을 수 있습니다.**
- 자격증 이미지는 강사에게 안내한 뒤에만 보냅니다.
- Anthropic은 API 입력을 기본적으로 모델 학습에 쓰지 않는 것으로 알고 있습니다(정책 재확인 필요).
- 샵 설정·본사 설정에서 AI를 끄면 모든 화면이 AI 없이 그대로 동작합니다.

### (c) 건강 정보(민감정보) 처리 근거와 암호화 범위 (작업 P21-9)

**초안·근거 위치**
| 내용 | 파일 |
|---|---|
| 보안 점검표 11항 개인정보(수집 항목·접근 범위·암호화·로그) | `docs/security/checklist.md` 11항 |
| 손님 메모·강습 노트의 건강 단어 감지·경고 | `src/lib/privacy/health.ts` |

**현재 상황**
- 건강 정보는 **받지 않는 것이 원칙**입니다. 입력란에 "부상·질환 등 건강 정보는 적지 마세요."라고 안내합니다.
- 그래도 메모에 "무릎 수술", "천식" 같은 내용이 들어갈 수 있습니다. 저장할 때 이런 단어가 있으면 경고를 띄우고, 경고 기록에는 원문 대신 걸린 단어만 남깁니다(저장은 막지 않습니다).
- 암호화: 비밀번호는 인증 서비스가 해시로 저장, 디스크는 Supabase 기본 저장 암호화. **열 단위 암호화는 없습니다.** 고유식별정보·계좌를 받지 않아 법정 암호화 대상은 없다고 보고 있으나 확인이 필요합니다.
- AI 상담의 손님 연락처는 별도로 암호화해 저장합니다(아래 d).

### (d) AI 상담 — 카카오톡·인스타그램 상담 글의 Anthropic 전송 (작업 P22)

**초안 위치**
| 내용 | 파일 |
|---|---|
| 설계 전체와 "사장님 결정", "개인정보 문구 초안" | `docs/ai-consult/README.md` |
| 처리방침에 넣을 문구 초안 | 같은 파일 "개인정보 문구 초안" 절 |

**무엇을 하나**: 렌탈샵이 카카오톡 채널·인스타그램 DM으로 받는 손님 문의에 AI가 돕습니다. 가격·영업시간·위치·정책처럼 샵이 적어 둔 안내 정보 범위의 질문은 AI가 바로 답하고(샵이 켠 경우만), 예약·금액 협상·불만·안내 정보 밖 질문은 사장님께 초안만 보여 주고 사람이 답합니다.

**처리 경로**: 손님 → ㈜카카오(카카오톡 채널 챗봇) 또는 Meta Platforms, Inc.(인스타그램, 미국) → 겨울파트너 서버 → Anthropic PBC(미국) → 겨울파트너 → 같은 경로로 답변.

**이미 정한 설계 원칙 (사장님 결정, 2026-11-05)**
- AI 자동응답은 기존 원칙("AI는 제안만")의 **유일한 예외**이며, 샵이 직접 켠 경우에만, 안내 정보 범위 사실만 답합니다.
- 손님 첫 자동 답변에 AI 답변임을 알립니다(기본 문구: "이 답변은 AI가 샵 안내 정보로 드리는 자동 답변이에요…").
- 글 속 전화번호·이메일은 가린 뒤 보냅니다. 손님 카카오·인스타 계정 id는 AI에 보내지 않고, 저장도 되돌릴 수 없는 해시로만 합니다.
- 손님 연락처는 암호화해 저장하고 화면에는 가운데를 가립니다(010-****-1234).
- 대화·메시지는 **90일 뒤 자동 삭제**. "강습 등록"으로 이어진 문의만 연락처를 지운 뒤 남깁니다.
- 실제 채널을 연결하기 전에는 처리방침을 바꾸지 않습니다(없는 처리를 미리 적지 않으려고).

## 3. 여쭙는 질문

번호마다 "필요/불필요", 필요하면 "무엇을 어디에 적어야 하는지"를 알려 주시면 그대로 반영하겠습니다.

**처리위탁·약관·처리방침 (a)**
1. 손님 정보는 샵이 처리자, 겨울파트너가 수탁자라는 구조가 맞습니까? 겨울파트너가 처리자로 봐야 하는 부분(예: 강사에게 레벨·메모 전달)이 있습니까?
2. 약관 7항(처리위탁)이 제26조 1항의 문서 요건을 채웁니까? 약관 동의만으로 위탁 문서를 갈음할 수 있습니까, 별도 위탁 계약서가 필요합니까?
3. 약관 7항의 **손해배상 범위**를 어떻게 정하는 것이 적절합니까(상한, 고의·중과실 예외 등)?
4. 정산·지급 기록 등 **거래 기록의 법정 보관 기간**과 대상은 무엇입니까? 보관 의무자가 샵인지 겨울파트너인지도 여쭙니다.
5. **샵 탈퇴 후 파기까지 기간**: 초안은 "내보내기 확인 후 또는 요청일로부터 30일"입니다. 적절합니까?
6. **백업 보관 주기**를 처리방침에 적어야 합니까? 적는다면 어떤 표현이 좋습니까(현재 Supabase 자동 백업 + 월 1회 수동 백업 검토 중)?
7. 손님 정보 보관 기간 "마지막 강습 후 3시즌 뒤 익명화"가 수집 목적에 비춰 적절합니까?
8. 손님 연락처 접속 기록 2년 보관이 적절합니까? (감사 기록 보존 기간도 정하지 못했습니다 — 작업 P21-10)
9. 개인정보 보호책임자는 대표 1인을 지정해도 됩니까? 처리방침에 어디까지(성명·직책·연락처) 적어야 합니까?

**국외 이전·재위탁 (a)(b)(d)**
10. **Anthropic(미국)으로 보내는 것**이 국외 이전에 해당합니까? 해당한다면 처리방침 고지(이전 국가·일시·방법·항목·보관 기간·거부 방법)만으로 됩니까, 손님·강사의 **별도 동의**가 필요합니까? 수탁자인 저희가 고지·동의를 받을 수 있습니까, 샵이 받아야 합니까?
11. **Vercel(미국 회사, 서버 함수는 서울 리전, 전송 구간·접속 기록은 해외를 거칠 수 있음)** 도 국외 이전 고지가 필요합니까?
12. **Anthropic의 데이터 보관 기간**을 처리방침에 적어야 합니까? (저희가 Anthropic 정책을 확인해 적을 예정입니다.) 적는 방식(예: "업체 정책에 따름" 가능 여부)을 알려 주십시오.
13. 접수 글 속 **처음 보는 손님 이름**이 Anthropic에 그대로 갈 수 있습니다. 고지만으로 허용됩니까? 허용되지 않으면 이름을 사람이 직접 골라 지우는 방식으로 바꾸겠습니다.
14. **강사 자격증 이미지**를 AI 판독에 보낼 때 강사의 **별도 동의**가 필요합니까, 안내로 충분합니까?
15. 샵용 위탁 고지 템플릿(`/shop/privacy-notice`)에서 AI를 쓰는 샵만 재위탁 줄을 게시하게 한 방식이 맞습니까?

**건강 정보 (c)**
16. 메모에 건강 내용이 들어갈 **가능성만으로** 민감정보 처리로 봐야 합니까? 그렇다면 **별도 동의**를 받아야 합니까, 아니면 "적지 마세요" 안내 + 경고로 충분합니까?
17. 민감정보가 들어갈 수 있는 메모 열에 **열 단위 암호화**가 필요합니까? 고유식별정보·계좌를 받지 않는 지금 구조에서 법정 암호화 대상이 따로 있습니까?

**AI 상담 (d)**
18. 손님 상담 글을 Anthropic에 보내는 것에 대해 **처리방침 고지만** 하면 됩니까, 손님 **동의**가 필요합니까? 첫 자동 답변의 고지 문구(위 기본 문구)가 충분합니까?
19. AI가 손님에게 **바로 답하는 것**(자동응답) 자체에 별도 고지·표시 의무가 있습니까?
20. 상담 기록 **90일 보존 후 삭제**, 강습 등록으로 이어진 문의만 연락처를 지우고 보존하는 방식이 적절합니까?
21. **㈜카카오, Meta Platforms, Inc.** 를 처리방침의 수탁자(또는 재수탁자)로 적어야 합니까? 손님이 스스로 카카오·인스타로 연락한 것이라 수탁자가 아니라고 볼 수 있습니까? Meta(미국)는 국외 이전 고지 대상입니까?
22. 손님 계정 id를 해시로만 저장하는 것이 가명처리로 인정됩니까? 처리방침에 어떻게 적어야 합니까?
