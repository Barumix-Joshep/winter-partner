# 메일 발송 설정 (가입 인증·비밀번호 재설정)

사장님이 직접 따라 하는 문서입니다. 가입·결제·설정 변경은 사장님이 하시고, 끝나면 "메일 설정 끝" 이라고만 알려 주세요. 비밀 값(API 키·SMTP 비밀번호)은 대화나 문서에 붙여 넣지 말고 Supabase 화면에만 넣습니다.

## 왜 필요한가
지금 Supabase 기본 메일은 시간당 몇 통만 보내고 스팸함에 잘 빠집니다. 시범 샵 사장님·강사가 가입 인증 메일이나 비밀번호 재설정 메일을 못 받으면 로그인을 못 합니다. 그래서 발송 전용 서비스를 연결합니다.

## 서비스 고르기

| | Resend (추천) | Amazon SES (대안) |
|---|---|---|
| 무료 | 월 3,000통, 하루 100통 | 첫 12개월 일부 무료(EC2 밖에서는 통당 과금) |
| 유료 | Pro 월 약 20달러에 월 50,000통 | 1,000통당 약 0.1달러 |
| 시작 난도 | 가입 → 도메인 추가 → DNS 3줄 → 끝 | AWS 계정·"샌드박스 해제" 신청(하루~며칠) 필요 |
| Supabase 연결 | SMTP 값 4개 | SMTP 값 4개 (리전별 주소) |

- **추천 근거**: 시범 기간 예상량(샵 5곳·강사 50명 가입·재설정, 월 수백 통)은 무료 한도 안입니다. 설정이 가장 짧고 화면이 쉬워 사장님이 혼자 끝낼 수 있습니다. 나중에 늘어나도 요금이 단순합니다.
- **대안(SES)**: 통수가 아주 많아지면 더 쌉니다. 대신 AWS 계정 관리와 발송 승인 절차가 있어 시범 단계에는 과합니다.
- 요금·한도는 2026년 11월 기준 기억으로 적었습니다. **가입 전에 각 서비스 요금 페이지에서 다시 확인**해 주세요.

## 1. 발송용 도메인 정하기
- 메일 보내는 주소는 회사 도메인이어야 스팸함에 덜 갑니다. 예: `no-reply@mail.<회사도메인>` (하위 도메인 `mail.`을 쓰면 회사 메일 설정과 섞이지 않습니다).
- 도메인이 아직 없으면 먼저 사야 합니다(가비아·후이즈·Cloudflare 등, 연 1~3만 원). 앱 주소(`winter-partner.vercel.app`)는 Vercel 소유라 메일 발송용으로 쓸 수 없습니다.

## 2. Resend 가입과 도메인 추가
1. resend.com 가입 (회사 메일 주소로).
2. **Domains → Add Domain** → `mail.<회사도메인>` 입력, 지역은 가까운 곳(도쿄 등)을 고릅니다.
3. 화면에 DNS 레코드가 나옵니다. 보통 아래 세 가지입니다.

## 3. DNS 레코드 넣기 (도메인 산 곳의 "DNS 관리" 화면)

| 종류 | 이름(호스트) | 값 | 하는 일 |
|---|---|---|---|
| TXT | `send.mail` (Resend 화면 그대로) | `v=spf1 include:amazonses.com ~all` 형태 | **SPF**: 이 서비스가 우리 이름으로 보내도 된다는 허락 |
| MX | `send.mail` | `feedback-smtp.<지역>.amazonses.com` (우선순위 10) | 반송 메일 받기 (SPF와 짝) |
| TXT | `resend._domainkey.mail` | `p=MIGf...` 긴 값 | **DKIM**: 메일이 위조되지 않았다는 서명 |
| TXT | `_dmarc.mail` | `v=DMARC1; p=none; rua=mailto:<받을 주소>` | **DMARC**: 위 둘이 실패한 메일을 어떻게 할지. 처음엔 `p=none`(보고만), 2주 문제없으면 `p=quarantine` |

- 값은 **Resend 화면에 나온 것을 그대로 복사**합니다(위 표는 모양 설명입니다).
- 저장 후 Resend에서 **Verify**를 누릅니다. 반영까지 몇 분~몇 시간 걸립니다. 모두 초록색(Verified)이 될 때까지 기다립니다.

## 4. SMTP 비밀번호(API 키) 만들기
- Resend **API Keys → Create API Key** → 이름 `supabase-smtp`, 권한 **Sending access**, 도메인 `mail.<회사도메인>`만.
- 키는 한 번만 보입니다. 바로 다음 단계 Supabase 화면에 붙여 넣고, 다른 곳에는 저장하지 않습니다.

## 5. Supabase에 SMTP 넣기
Supabase 대시보드 → 프로젝트 `winter-partner` → **Authentication → Emails → SMTP Settings** (화면 이름은 바뀔 수 있습니다. "SMTP"로 찾으면 나옵니다) → **Enable Custom SMTP** 켬.

| 칸 | 값 |
|---|---|
| Sender email | `no-reply@mail.<회사도메인>` |
| Sender name | `겨울파트너` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | `<4단계에서 만든 API 키>` ← 비밀 값, 여기에만 |
| Minimum interval | 기본값(60초) 그대로 |

저장 후 같은 메뉴의 **Rate Limits**에서 "이메일 발송 한도(시간당)"를 30 정도로 올립니다(기본값은 아주 낮음). 이것은 운영 설정 변경이니 사장님이 직접 하시고 저에게는 결과만 알려 주세요.

**URL 설정 확인**: Authentication → URL Configuration → Site URL이 `https://winter-partner.vercel.app`, Redirect URLs에 `https://winter-partner.vercel.app/**`가 있어야 메일 링크가 앱으로 돌아옵니다(앱은 `/auth/confirm`에서 받습니다).

## 6. 메일 문구 (Authentication → Emails → Templates)
링크 자리 `{{ .ConfirmationURL }}`는 그대로 둡니다.

**Confirm signup (가입 인증)**
- 제목: `[겨울파트너] 이메일 주소를 확인해 주세요`
- 본문:
```html
<p>안녕하세요, 겨울파트너입니다.</p>
<p>가입을 마치려면 아래 버튼을 눌러 이메일 주소를 확인해 주세요. 링크는 24시간 동안 쓸 수 있습니다.</p>
<p><a href="{{ .ConfirmationURL }}">이메일 확인하고 시작하기</a></p>
<p>직접 가입하지 않으셨다면 이 메일은 무시하셔도 됩니다.</p>
<p>겨울파트너 드림</p>
```

**Reset password (비밀번호 재설정)**
- 제목: `[겨울파트너] 비밀번호 재설정 안내`
- 본문:
```html
<p>안녕하세요, 겨울파트너입니다.</p>
<p>아래 버튼을 눌러 새 비밀번호를 정해 주세요. 링크는 1시간 동안 한 번만 쓸 수 있습니다.</p>
<p><a href="{{ .ConfirmationURL }}">새 비밀번호 정하기</a></p>
<p>요청하지 않으셨다면 이 메일은 무시하셔도 됩니다. 비밀번호는 바뀌지 않습니다.</p>
<p>겨울파트너 드림</p>
```

**Change email (이메일 변경)** — 쓰면: 제목 `[겨울파트너] 새 이메일 주소를 확인해 주세요`, 본문은 가입 인증과 같게.

## 7. 끝난 뒤 확인
1. 시크릿 창에서 앱 가입 화면 → 본인이 받는 **지메일·네이버 메일** 두 곳으로 각각 [테스트] 가입.
2. 1분 안에 받은편지함에 오는지, **스팸함**에 가지 않았는지 확인.
3. 메일의 버튼을 눌러 앱으로 돌아와 로그인되는지 확인.
4. 로그인 화면 "비밀번호를 잊었어요" → 재설정 메일 → 새 비밀번호로 로그인.
5. 지메일에서 메일 열기 → 오른쪽 위 ⋮ → **원본 보기**: `SPF: PASS`, `DKIM: PASS`, `DMARC: PASS`가 보이면 정상.
6. 결과(받은편지함/스팸함, PASS 여부)를 알려 주시면 `docs/pilot-device-check.md` 표에 적고, 테스트 계정은 "삭제 승인" 때 함께 지웁니다.

## 문제가 생기면
- 메일이 안 온다: Resend **Logs**에 기록이 있는지 → 없으면 Supabase SMTP 값 오타, 있으면 받는 쪽 스팸함.
- 스팸함으로 간다: DNS 3개가 모두 Verified인지, 보내는 주소 도메인과 DKIM 도메인이 같은지.
- 링크를 누르면 "확인하지 못했습니다": Redirect URLs 설정, 링크가 만료(24시간)됐는지.
