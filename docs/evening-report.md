## [3] CI 사각: 오후 지적 정정과 보완 (PR #51)
**정정합니다.** 오후 보고서의 "main 푸시 때 db·unit CI가 돌지 않는다"는 틀린 내용이었습니다.
- `ci.yml`은 원래 `push: branches: [main]`에서도 unit·db·e2e-core를 모두 돕니다.
- #46 → #45 순서로 합친 상태(`b0a7788`)도 main 실행 42157463999에서 12:38~12:45에 세 작업 모두 통과했습니다.

실제 사각은 두 가지입니다.
1. **main 실행이 실패해도 알림이 없습니다.** e2e-full·post-deploy에는 실패 이슈가 있지만 ci에는 없었습니다. → #51이 `report-failure` 작업을 추가합니다. main 푸시에서 셋 중 하나라도 실패하면 이슈 "main CI 실패 (병합 뒤)"를 남기고, 같은 제목의 열린 이슈가 있으면 댓글을 답니다. `docs/ci.md` 표도 갱신했습니다.
2. **main 실행은 병합(=배포)과 동시에 돌아서 깨진 배포를 막지는 못합니다.** 막는 방법은 브랜치 보호 "Require branches to be up to date before merging"이고, 사장님 설정이라 건드리지 않았습니다.

**CI 시간**
- PR: 변화 없습니다(새 작업은 skipped).
- main 푸시: 성공하면 변화 없습니다. 실패할 때만 이슈 작업이 10~20초 돕니다.
- 브랜치 보호 "최신 main 필요"를 켜면 연속으로 병합할 때 PR마다 CI를 한 번 더 돌아야 해서 PR당 약 7.5분이 늘어납니다.
